# ConvertFrom-SmartCsv

## SYNOPSIS

Parses a CSV-formatted string into PSObjects with automatic type inference.

## SYNTAX

```
ConvertFrom-SmartCsv [-CsvInput] <String> [-ProgressAction <ActionPreference>] [<CommonParameters>]
```

## DESCRIPTION

ConvertFrom-SmartCsv parses a CSV-formatted string and returns PSObjects with property values automatically converted to their most appropriate .NET types. Unlike the built-in ConvertFrom-Csv, which returns every value as a string, ConvertFrom-SmartCsv inspects all values in each column and infers the best type for that column.

Type inference evaluates columns in this order:

1. **Boolean** — All non-null values are "true" or "false" (case-insensitive), or all integer values are only "0" and "1".

2. **Int32** — All non-null values are whole numbers (at least one value outside the 0/1 range).

3. **Decimal** — All non-null values are numbers and at least one has a fractional part.

4. **DateTime** — All non-null values parse as dates using the invariant culture.

5. **String** — Any column that does not satisfy the above conditions.

Inference is column-wide. Every non-null value in a column must be compatible with the inferred type. If any value in a column is incompatible, the column falls through to the next type in the hierarchy, eventually landing on String.

The text "null" (case-insensitive) is treated as a null value in all column types and does not affect type inference. Blank whitespace-only values are also treated as null. Numbers are parsed using the invariant culture, meaning a period (.) is expected as the decimal separator.

The first line of the input string is always treated as the header row. Each header cell name becomes a property name on the output PSObjects.

## EXAMPLES

### Example 1: Parse a simple CSV string

```powershell
"Id,Name,Age`n1,Alice,21`n2,Bob,20" | ConvertFrom-SmartCsv
```

```
Id Name  Age
-- ----  ---
 1 Alice  21
 2 Bob    20
```

The Id and Age columns are returned as Int32, not String, because all values in those columns are whole numbers. Name is returned as String.


### Example 2: Type inference across multiple types

```powershell
$csv = "Active,Count,Price,Joined`ntrue,5,9.99,2023-01-15`nfalse,12,4.50,2023-06-01"
$csv | ConvertFrom-SmartCsv | Select-Object -First 1 | ForEach-Object {
    "Active: $($_.Active.GetType().Name) = $($_.Active)"
    "Count:  $($_.Count.GetType().Name)  = $($_.Count)"
    "Price:  $($_.Price.GetType().Name)  = $($_.Price)"
    "Joined: $($_.Joined.GetType().Name) = $($_.Joined)"
}
```

```
Active: Boolean = True
Count:  Int32   = 5
Price:  Decimal = 9.99
Joined: DateTime = 1/15/2023 12:00:00 AM
```

Each column is inferred independently. Active becomes Boolean, Count becomes Int32, Price becomes Decimal, and Joined becomes DateTime.


### Example 3: Here-string input

```powershell
$csv = @"
ProductId,Name,InStock,Price
101,Widget,true,14.99
102,Gadget,false,29.99
103,Doohickey,true,7.50
"@

$csv | ConvertFrom-SmartCsv | Where-Object { $_.InStock -and $_.Price -lt 10 }
```

```
ProductId Name      InStock Price
--------- ----      ------- -----
      103 Doohickey    True  7.50
```

A PowerShell here-string is a convenient way to embed multi-line CSV data directly in a script. Because InStock is Boolean and Price is Decimal, the Where-Object filter performs typed comparisons rather than string comparisons.


### Example 4: Null handling

```powershell
"Id,Score`n1,95`n2,null`n3,82" | ConvertFrom-SmartCsv
```

```
Id Score
-- -----
 1    95
 2
 3    82
```

The text "null" in the Score column is converted to $null on the output PSObject. The Score column is still inferred as Int32 because "null" is excluded from type inference. The row where Score is $null produces a PSObject with a $null Score property.

## NOTES

- Type inference is column-wide. All non-null values in a column must be compatible with the inferred type.
- "null" (case-insensitive) and blank/whitespace values are treated as $null and do not affect type inference.
- Integer values consisting only of "0" and "1" are inferred as Boolean, not Int32. If any integer value in the column is outside that range, the column is inferred as Int32.
- Numbers are parsed using the invariant culture. Use a period (.) as the decimal separator. Comma-formatted numbers (e.g., "1,000") are not supported.
- Dates are parsed using DateTime.TryParse with the invariant culture. ISO 8601 format (e.g., "2024-01-15") is recommended for unambiguous parsing.
- If a column contains values that match more than one type (for example, both Boolean and numeric), an error is thrown. This indicates a malformed or mixed-type column.
- Header cell names are trimmed of leading and trailing whitespace.

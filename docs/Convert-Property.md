# Convert-Property

## SYNOPSIS

Converts a named property on each input object to the specified .NET TypeCode.

## SYNTAX

```
Convert-Property [-InputObject] <PSObject[]> [-Property] <String> [-Type] <TypeCode>
 [-ProgressAction <ActionPreference>] [<CommonParameters>]
```

## DESCRIPTION

`Convert-Property` takes a stream of objects and returns new PSObject copies where the named property has been converted to the target .NET TypeCode (e.g., `Int32`, `DateTime`, `Boolean`). It does not mutate the original objects.

This is particularly useful after `Import-Csv` or `ConvertFrom-Csv`, which always produce string-typed properties. Pipe the output through one or more `Convert-Property` calls to restore the correct types before passing data to code that expects typed values.

Conversion behavior:

- String property values are parsed using invariant culture (period as decimal separator, ISO 8601 date formats).

- The string `"null"` is treated as a null value.

- The strings `"1"` and `"0"` are converted to `$true` and `$false` respectively for Boolean targets.

- Non-string values use `System.Convert.ChangeType` with invariant culture.

If the named property does not exist on an object, that object passes through unchanged with no error. If conversion fails (invalid format, overflow, or invalid cast), a non-terminating error is written and the original object passes through unchanged, allowing the pipeline to continue processing remaining objects.

## EXAMPLES

### Example 1: Convert a string property to Int32 after CSV import

```powershell
$data = Import-Csv -Path .\employees.csv
# All properties are strings after Import-Csv

$data = $data | Convert-Property -Property 'Age' -Type Int32

$data | Where-Object { $_.Age -gt 30 }
```

`Import-Csv` produces string-typed properties. Convert `Age` to `Int32` so that numeric comparisons work correctly.


### Example 2: Convert a string property to DateTime

```powershell
$events = Import-Csv -Path .\audit-log.csv

$events = $events | Convert-Property -Property 'Timestamp' -Type DateTime

$events | Where-Object { $_.Timestamp -gt (Get-Date).AddDays(-7) }
```

Date strings in the CSV are parsed using invariant culture. After conversion, standard PowerShell date comparisons work as expected.


### Example 3: Chain multiple conversions in a pipeline

```powershell
Import-Csv -Path .\orders.csv |
    Convert-Property -Property 'Quantity'   -Type Int32   |
    Convert-Property -Property 'UnitPrice'  -Type Decimal |
    Convert-Property -Property 'OrderDate'  -Type DateTime |
    Convert-Property -Property 'IsShipped'  -Type Boolean
```

Pipe through `Convert-Property` once per property that requires type correction. Each step produces new PSObjects with that property converted; all other properties are passed through unchanged.


### Example 4: Observe error handling when a value cannot be converted

```powershell
$rows = @(
    [PSCustomObject]@{ Id = '1'; Score = '95'  }
    [PSCustomObject]@{ Id = '2'; Score = 'N/A' }
    [PSCustomObject]@{ Id = '3'; Score = '82'  }
)

$rows | Convert-Property -Property 'Score' -Type Int32
```

Row 2 cannot be converted because `'N/A'` is not a valid integer. A non-terminating error is written for that row and the original object (with `Score` still a string) is passed through. Rows 1 and 3 are converted successfully. Processing is not interrupted.

## NOTES

- Creates new PSObject copies; original input objects are not mutated.
- Uses invariant culture for parsing: period (`.`) is the decimal separator and dates should be in ISO 8601 or other invariant-culture-compatible formats.
- The strings `"1"` and `"0"` map to `$true` and `$false` for Boolean conversions.
- The string `"null"` is treated as a null value regardless of target type.
- Conversion failures (format errors, overflows, invalid casts) produce non-terminating errors. The original object passes through unchanged, so downstream steps may need to handle mixed types.
- If the named property does not exist on an object, that object passes through silently with no error.
